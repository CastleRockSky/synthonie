# Synthonie

A simple soundscape, music-loop and sound-effect maker for an RPG video game. It is built for someone who finds real music software overwhelming: one screen, a handful of ideas, instant sound, and a codebase arranged so new features can be added one at a time as he learns.

The spec, design principles and roadmap are in [docs/SPEC.md](docs/SPEC.md).

## What it does (v0.1)

- **Sound library**: 20 built-in sounds generated by code (wind, rain, fire, stream, drone, crickets, thunder, bird, owl, a drum kit, and game effects like coin, sword, footstep, magic). Import WAV/MP3/OGG files, or record from the microphone with a live meter and automatic silence trimming.
- **Soundscape**: stack sounds as layers. Each layer loops forever, plays once, or plays at random intervals (owls, thunder), with Volume, Left/Right, Pitch, Muffle (low-pass) and Space (reverb) sliders.
- **Beat Maker**: a 16- or 32-step drum grid where any sound can be a drum, plus a tune grid that only offers notes from a pentatonic scale (Happy or Spooky) so anything drawn sounds fine. Five synth instruments, tempo and swing. Everything can be changed while it plays.
- **Export** a stereo OGG (what RPG Maker, Godot and Unity read; about a tenth the size) or WAV of any length, optionally as a seamless loop. For RPG Maker, drop the `.ogg` into the project's `audio/bgm` (music), `audio/bgs` (ambience) or `audio/se` (effects) folder. RPG Maker MZ and desktop MV play `.ogg` as is; MV's browser and mobile builds also want an `.m4a` copy, which the app does not make yet.
- **Save** everything (including recordings) in one `.synthonie` file, and autosave so an accidental close loses nothing.

## Installing on another PC

The app ships as a normal Windows installer, so the PC it runs on needs nothing else: no Node.js, no terminal.

1. On your own machine, build the installer once (needs Node.js 20 or newer):

   ```bash
   npm install
   ```

   ```bash
   npm run package
   ```

   This type-checks and bundles the web app, then wraps it in Electron and writes `release/Synthonie-Setup-<version>.exe` (about 100 MB; the first build also downloads the Electron and NSIS tooling). Once releases are set up (next section) you can skip this and download the installer from the repo's Releases page instead.

2. Copy that `.exe` to the other PC (USB stick, OneDrive, whatever) and double-click it. It installs for the current user only, with no admin prompt, into `%LOCALAPPDATA%\Programs\synthonie`, puts **Synthonie** on the desktop and in the Start menu, and opens the app.

3. The installer is not code-signed, so Windows SmartScreen will show "Windows protected your PC" the first time. Click **More info**, then **Run anyway**. That happens once.

Good to know:

- **Microphone**: the app asks Windows for the microphone the first time you press Record. If recording says no microphone was found, check Settings → Privacy & security → Microphone, and make sure "Let desktop apps access your microphone" is on.
- **Files**: Save, Open and Export use the normal Windows dialogs and start in Documents. Save overwrites the file you opened without asking; Save as asks for a new one.
- **Project files**: the installer registers `.synthonie` (and the older `.zekeproj`) with Windows, so double-clicking a project in Explorer opens it in Synthonie (in the window that is already open, if the app is running), and Save then overwrites that file without asking.
- **Coming from "Zeke Synth"** (the v0.1 name): just install Synthonie. On its first run it copies the old app's autosave over, and it still opens `.zekeproj` files. Then uninstall Zeke Synth from Settings → Apps; it is a separate program as far as Windows is concerned.
- **Autosave** lives in `%APPDATA%\Synthonie`, so closing the window without saving loses nothing. Uninstalling (Settings → Apps) leaves that folder in place.
- **Updating** is automatic once releases are published on GitHub (next section). The app checks shortly after it opens and every few hours, downloads the new installer in the background, and asks to restart; "Later" installs it the next time the app is closed. Running a newer installer by hand still works too.
- **F12** opens the developer tools inside the app, which is handy if something goes wrong on his PC. The desktop shell also writes a log to `%APPDATA%\Synthonie\logs\main.log`, including every update check, so "send me the log" is a real option.

## Releasing a new version (auto-update)

Releases are built by GitHub Actions and published as GitHub Releases, and the installed app updates itself from them. The repository has to be **public** for that: the updater downloads release files without any login, and a private repo would need a token baked into every installed copy.

One-time setup:

1. Create the public repo named in `package.json` under `build.publish` (currently `CastleRockSky/synthonie`) and push this code to it. With the GitHub CLI logged in:

   ```bash
   gh repo create CastleRockSky/synthonie --public --source=. --remote=origin --push
   ```

2. Nothing else: the workflow in `.github/workflows/release.yml` runs on the free Windows runner with the token GitHub provides, so there are no secrets to add.

Every release after that:

```bash
npm version minor
```

```bash
git push --follow-tags
```

`npm version` bumps `package.json` (use `patch`, `minor` or `major`), commits, and tags the commit `v0.2.0`. Pushing the tag starts the workflow, which runs the tests, builds `Synthonie-Setup-0.2.0.exe` and publishes it as a release together with `latest.yml`, the small file the installed app polls. Expect about five minutes; watch it under the repo's Actions tab. Any installed copy picks the new version up within a few hours, or straight away at the next launch.

Good to know:

- Only tags that look like `v1.2.3` trigger a release. A plain `git push` of commits publishes nothing.
- `npm run package` builds the installer locally and never publishes. `npm run release` is what the workflow runs; it publishes to GitHub and needs a `GH_TOKEN` environment variable if run by hand.
- The first installer still has to reach his PC by hand (download it from the release page). From then on it updates itself.
- Updates are unsigned, like the installer, so the first manual install shows the SmartScreen prompt; the automatic updates do not.

## Running it for development

Requirements: [Node.js](https://nodejs.org) 20 or newer. The web app itself runs in Microsoft Edge or Google Chrome.

```bash
npm install
```

```bash
npm run dev
```

Then open http://localhost:5173. This is the plain browser workflow and is unchanged by the desktop packaging.

Other scripts:

- `npm run desktop`: the Electron window against the same dev server, so edits hot-reload inside the real shell (native dialogs, microphone permission, autosave in `%APPDATA%\Synthonie`).
- `npm run package`: build the installer into `release/` (see above), without publishing. `release/win-unpacked/Synthonie.exe` is the same app without the installer.
- `npm run release`: the same build, published to GitHub Releases. This is what the release workflow runs.
- `npm run build` (type-check and bundle to `dist/`), `npm test` (unit tests for the pure audio helpers and the project file format), `npm run typecheck`.
- `npm run icon`: regenerate `build/icon.png` and `build/icon.ico` from `scripts/make-icon.mjs`.
- `npm start` / `start.bat`: the older no-installer way, which serves `dist/` locally and opens an Edge app window. Still works, but needs Node on that PC.

In the browser DevTools console (or F12 inside the desktop app), `synthonie.engine`, `synthonie.bank` and `synthonie.store.getState()` expose the running app.

## How the code is organised

| Folder | What lives there |
|---|---|
| `src/model/` | The `Project` document (`types.ts`), the starter project and helpers (`defaults.ts`), and every state change (`store.ts`). |
| `src/audio/` | `engine.ts` builds the Web Audio graph for live playback and for export from the same code. `builtins.ts` generates the built-in sounds. `synth.ts` holds the melody instruments as data. `scales.ts`, `recorder.ts`, `reverb.ts`, `wav.ts`, `ogg.ts` (Vorbis encoder, loaded on first export), `dsp.ts` (pure helpers with tests). |
| `src/files/` | The `.synthonie` zip format, save/open dialogs (`fs.ts`, which uses the desktop bridge when present, else the browser's File System Access API, else download/upload), the desktop bridge types (`desktop.ts`), IndexedDB autosave. |
| `src/ui/` | React components, one per screen area. |
| `src/app/` | Startup (`boot.ts`), the engine and sound bank singletons, and the button actions (`actions.ts`). |
| `electron/` | The desktop shell: `main.cjs` opens the window, allows the microphone, shows the native file dialogs, hands over a project that was double-clicked in Explorer, and checks GitHub Releases for updates; `preload.cjs` exposes the few file calls to the page as `window.synthonieDesktop`. |
| `.github/workflows/` | `release.yml` builds and publishes the installer when a `v*` tag is pushed. |
| `build/` | The app icon used by the installer and the window. |
| `scripts/` | Launchers and the icon generator. |

There is no audio framework in between: the engine uses the Web Audio API directly, so every sound can be traced from a slider to the node that makes it. The desktop shell is the same web build loaded from `dist/`; the page never sees Node or Electron, only the small bridge. Everything the page uses is bundled by Vite, which is why those libraries are devDependencies. The only runtime `dependencies` are `electron-updater` and `electron-log`, which the main process needs as real modules, so the installer contains `dist/`, `electron/` and those two.

## Growing it

Each roadmap item in the spec is meant to be a small, separate change. Some first steps that fit the current structure:

- **A new built-in sound**: write a generator in `src/audio/builtins.ts` and add it to the `BUILTINS` list.
- **A new instrument**: add an entry to `INSTRUMENTS` in `src/audio/synth.ts`.
- **A new scale**: add an entry to `SCALES` in `src/audio/scales.ts`.
- **A new layer control** (say, a fade-in): add the field to `Layer` in `types.ts`, a default in `defaults.ts`, a slider in `Soundscape.tsx`, and use it in `LayerVoice` in `engine.ts`.
- **Something only the desktop app can do** (a list of recent projects, say): add an IPC handler in `electron/main.cjs`, expose it in `electron/preload.cjs`, and type it in `src/files/desktop.ts`. Opening a double-clicked `.synthonie` (`onOpenProject`) is a small worked example of exactly that.

Project files carry a `version` number; when the format changes, bump it and add an upgrade step in `migrate()` in `src/files/project-file.ts` so old projects keep opening.

## Known limits

- In a browser, Edge or Chrome only (the save dialogs and microphone recording use APIs Firefox and Safari lack). The desktop app has no such limit.
- One beat pattern per project; no song arrangement yet.
- OGG exports loop as a whole. RPG Maker's intro-then-loop songs (its `LOOPSTART` / `LOOPLENGTH` tags) are not written yet.
- The installer is Windows-only and unsigned (see the SmartScreen note above).
